# 手段1：EDINETから有報XBRLを手動ダウンロードする手順

> ハンズオン当日、参加者が **APIキーなし・ブラウザだけ** で対象企業の有価証券報告書XBRLを取得するための手順。
> 本命＝**ＡＲＥホールディングス（証券コード5857）**。APIキー登録（手段0）や事前配布（手段2）が使えない/使わない場合の標準ルート。

- **所要**：2〜3分／人
- **必要なもの**：ブラウザ（Chrome等）と、`disclosure2.edinet-fsa.go.jp` への通信許可のみ
- **APIキー不要・ログイン不要**
- 検証日：2026-09-09（実機で全ステップ確認済み）

---

## ⚠️ 最重要ポイント（当日ハマる筆頭）

**提出者証券コードは「5857」ではなく「58570」と入力する。**
EDINETは社内で5桁の証券コード（4桁＋末尾0）で管理しており、`5857` で検索すると **「レコードがありません」** になります。必ず末尾に `0` を付けて **`58570`** と入力してください。
（コードを覚えていない場合は、後述のとおり **提出者名称に「ＡＲＥホールディングス」** と入れてもOK）

---

## 手順

### STEP 1. EDINET（開示書類の閲覧サイト）を開く
ブラウザで下記を開く。
```
https://disclosure2.edinet-fsa.go.jp/
```

### STEP 2. 「書類詳細検索」を開く
画面上部のメニューから **「書類詳細検索」** をクリック。直接この URL でも可。
```
https://disclosure2.edinet-fsa.go.jp/weee0050.aspx
```

### STEP 3. 検索条件を入力する
「書類提出者情報を指定する」ブロックで、次のどちらかを入力：

| 入力欄 | 値 | 備考 |
|--------|-----|------|
| **提出者証券コード** | **`58570`** | ★末尾の `0` を忘れない（`5857`ではヒットしない） |
| （代替）**提出者名称** | `ＡＲＥホールディングス` | コードが不安ならこちらが確実。全角でOK |

- 必要なら上部の **「XBRLを含む書類のみを検索対象とする」** にチェックを入れると、XBRLのある書類だけに絞れる。
- 期間で絞りたい場合は「決算期／提出期間を指定する」を開いて指定（通常は未指定でよい）。

### STEP 4. 「検索」を押す
提出者情報ブロック内の **「検索」** ボタンをクリック。画面下部に結果一覧が出る（ARE の場合 約9件）。

### STEP 5. 目的の書類（有価証券報告書）を見つける
一覧から下記の行を探す：

| 提出日時 | 提出書類 | コード | 提出者 |
|----------|----------|--------|--------|
| 2026/06/15 15:54 | **有価証券報告書－第17期(2025/04/01－2026/03/31)** | E21187 | ＡＲＥホールディングス株式会社 |

> 一覧には内部統制報告書・確認書・半期報告書なども並ぶので、**「有価証券報告書－第17期」** の行を選ぶこと。

### STEP 6. XBRL（またはCSV）をダウンロードする
その行の右側にある列のリンクをクリック：

- **`XBRL`** 列 … クリックで **XBRL一式のZIP** がダウンロードされる（本ハンズオンのメイン教材）
- **`CSV`** 列 … クリックで **数値のCSV版ZIP** がダウンロードされる（"答え合わせ"や時短用）
- `PDF表示` 列 … 人が読む用のPDF（参考）

以上で取得完了。

## ダウンロードしたZIPの中身（XBRL）

解凍すると、おおよそ次の構成（ファイル名の `E21187` `2026-03-31` は企業・決算期で変わる）：

```
XBRL/
├─ PublicDoc/                         ← 有報の本体（これがメイン）
│   ├─ jpcrp030000-asr-001_E21187-000_2026-03-31_..._.xbrl   ← XBRLインスタンス（数値の実体）
│   ├─ ...-.xsd / _cal.xml / _def.xml / _lab.xml / _pre.xml  ← タクソノミ／リンクベース（構造・ラベル）
│   ├─ 0101010_honbun_..._ixbrl.htm 〜                        ← 本文（iXBRL）
│   └─ images/                                                ← 図表
└─ AuditDoc/                          ← 監査報告書
```

- **主要財務数値は `PublicDoc` の `...asr....xbrl`（＋タクソノミ）に入っている。**
- CSV版ZIPは `XBRL_TO_CSV/...asr....csv`（**UTF-16・タブ区切り**）で、`要素ID / 項目名 / コンテキストID / 相対年度 / 連結・個別 / 単位 / 値` の表形式。「経営指標等」タグに**5年分の時系列**が入っていて扱いやすい。

### 動作確認（任意）
ダウンロードしたZIPを解凍し、`PublicDoc` に `.xbrl` と `_pre.xml`/`_lab.xml` 等が揃っていればOK。これが揃っていれば Claude Code に解析させられる。

## つまずきポイントと対処

| 症状 | 原因 | 対処 |
|------|------|------|
| 「レコードがありません」 | 証券コードを `5857`（4桁）で入力した | **`58570`** と5桁で入力。または提出者名称で検索 |
| それでも出ない | 期間指定が狭い／会社名の表記ゆれ | 「決算期／提出期間」を未指定に。名称は「ＡＲＥ」など一部でも可 |
| ダウンロードが始まらない | ブラウザのダウンロードブロック／ポップアップブロック | ダウンロードを「許可」。企業PCのDL制限がある場合はIT許可を確認 |
| どの行か分からない | 同社の複数書類が並ぶ | 「**有価証券報告書－第◯期**」の行を選ぶ（内部統制報告書・確認書ではない） |
| そもそもサイトが開けない | PCが `disclosure2.edinet-fsa.go.jp` に出られない | egress許可をITに確認。閉じている場合は**手段2（事前配布）**に切替 |

## 横展開（別企業への適用）

同じ手順で、証券コードを**5桁**（4桁＋0）にして入れるか、提出者名称を入れるだけ。例：

| 企業 | 提出者証券コード（5桁） | 会計基準 | 備考 |
|------|------------------------|----------|------|
| ＡＲＥホールディングス | `58570` | IFRS | 本命 |
| 松田産業 | `74560` | 日本基準 | 貴金属リサイクルの同業。**横展開デモの2社目として検証済み** |
| ＤＯＷＡホールディングス | `57140` | 日本基準 | 非鉄・リサイクルの同業 |
| 住友金属鉱山 | `57130` | 日本基準 | 非鉄大手 |

> 2社目以降も「有価証券報告書－第◯期」の行から XBRL/CSV をDLする流れは同一。スキル `edinet-xbrl-dashboard` はIFRS（ARE）・日本基準（松田産業）の**両方で無改修適用できることを実データで確認済み**。

## 手段2（事前配布）との関係

- **手段1**＝当日ライブでEDINETからDL。「自分で取れた」体験になるが、通信許可・DL制限に依存。
- **手段2**＝ファシリテーターが上記手順で事前取得したZIPを配布。確実に回る安全網。
- 推奨：**代表者が手段1をデモ → 各自の課題は手段2の配布データで確実に進める**（叩き台の「ライブ＝ハッピーパス／配布＝安全網」の二段構え）。
- 手段2の配布データは本リポジトリの `data/ARE_E21187/`（`S100YBFP_xbrl.zip` / `S100YBFP_csv.zip`）に保存済み。
