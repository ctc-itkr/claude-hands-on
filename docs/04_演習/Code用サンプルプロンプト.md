# Claude Code ハンズオン用 サンプルプロンプト集

第2回（実機）で、参加者がコピペして使えるプロンプトのたたき台です。目玉シナリオ「EDINETのXBRL → localhostダッシュボード → スキル化 → 他社横展開」に沿って課題0〜4を用意。各課題に **プロンプト（コピペ用）／狙い／想定つまずき・助け舟** を付けています。

> 前提の共有（冒頭で説明）
> - 配布データの置き場所：`./data/edinet/<会社コード>/`（例：`./data/edinet/5857/` に AREホールディングスのXBRL一式）
> - 成果物の置き場所：`./output/`
> - 実行環境：デスクトップアプリ＋Bedrock。`pip` は環境方針に従う（社内ミラー到達可なら随時、不可なら同梱ライブラリ／標準ライブラリのみ）
> - まず各自の作業フォルダで `claude` を起動（デスクトップアプリの場合は対象フォルダを開く）

---

## 課題0：ウォームアップ（成功体験を全員に）

**プロンプト（コピペ）**
```
金の重量(g)と純度(%)を入力すると買取概算額を計算できる、単一HTMLのツールを作ってください。
・外部ライブラリは使わず、1ファイル(index.html)で完結
・入力はブラウザ上のフォーム、計算はその場で表示
・グラム単価は仮に9,000円/g をコード内の定数として、あとで変えやすくコメントを付ける
作成後、ローカルで開いて動作を確認する手順も教えてください。
```

**狙い**：「自然言語 → 動くもの → ローカルで確認」を全員が一度体験する。Claude Codeがファイルを作る／実行を促す流れに慣れる。

**想定つまずき・助け舟**
- ファイルがどこにできたか分からない → 「作ったファイルのパスを教えて」「そのファイルをブラウザで開いて」と続ける。
- 権限確認のダイアログで戸惑う → 何を実行しようとしているかを読む練習として扱う。

## 課題1：配布XBRLを解析して主要財務数値を抽出

**プロンプト（コピペ）**
```
./data/edinet/5857/ に、ある上場企業の有価証券報告書のXBRL一式があります。
この中から直近5期分の主要財務数値（売上高・営業利益・経常利益・当期純利益・自己資本比率・EPS）を
抽出して、./output/financials.json に整形して保存する Python スクリプトを作ってください。

重要な進め方：
・XBRLは巨大なので、ファイル全体を読み込んで会話に貼らないこと。まずディレクトリ構成と
  ファイル種別を調べ、どの要素(タグ/コンテキスト)を使うかの当たりをつけてからスクリプト化する。
・抽出に使ったタグ名と対応づけ（マッピング）も ./output/mapping.md に残す。
・実行して financials.json の中身を確認し、値がおかしければ直す。
```

**狙い**：XBRLの複雑さ（タクソノミ／コンテキスト／ディメンション）をClaude Codeに解かせる。**生データを丸ごとコンテキストに載せず、スクリプトで処理して結果だけ確認する**という、トークン・コストの節約作法をここで体得する。

**想定つまずき・助け舟**
- タグの対応が合わず値がずれる → 「どのコンテキスト(期間・連結/単体)を採用したか説明して」「連結・通期の値を採用して」と具体化。
- ライブラリ不足で失敗 → 環境方針に応じて「標準ライブラリ(ElementTree)だけで書き直して」または同梱ライブラリを指定。
- 会話が重くなる → 「XBRL本文は貼らず、要約と対象タグだけ教えて」と誘導。

## 課題2：抽出結果から単一HTMLダッシュボードを作る（試行錯誤）

**プロンプト（コピペ）**
```
./output/financials.json を読み込んで、単一のHTMLファイル ./output/dashboard.html を作ってください。
要件：
・外部ライブラリ/CDNは使わず、1ファイルで完結（チャートはインラインSVGかCSSで描画）
・上部にKPIカード（売上高・営業利益・経常利益・当期純利益・自己資本比率・EPS）
・売上高の推移（棒グラフ）と利益の推移（営業利益・当期純利益）を表示
・ライト/ダーク両対応、数値はサンプルではなく financials.json の値を使う
・localhost で確認できるよう、簡易サーバの起動コマンドも教えて（例：python -m http.server）
出来たらブラウザで開いて、レイアウト崩れがないか一緒に確認しましょう。
```

**狙い**：抽出データ → 可視化までを通し、「localhostで動くダッシュボード」に到達。エージェントが自分で直しながら仕上げる反復を体感（＝内製化の実感、「簡単」「すごい」の演出）。

**想定つまずき・助け舟**
- 見た目が地味／崩れる → 「KPIをカード化して」「余白と配色を整えて」「棒の上に数値ラベルを付けて」と1つずつ指示。
- ダーク時に文字が見えない → 「ダークモードの配色を別に定義して」。
- localhostが開けない → ポート指定や起動フォルダを確認（「output フォルダで http.server を8000番で起動して」）。

## 課題3：一連の手順を SKILL.md にスキル化

**プロンプト（コピペ）**
```
課題1〜2でやった「配布XBRL → 主要財務数値の抽出 → 単一HTMLダッシュボード生成」の一連の手順を、
再利用できるスキルにまとめてください。
・skills/edinet-dashboard/SKILL.md として作成
・入力（XBRLフォルダのパス）と出力（financials.json と dashboard.html）を明記
・抽出タグのマッピングや、つまずきやすい点（連結/単体、通期、単位）も手順に含める
・別の会社のXBRLでもそのまま使えるよう、会社固有の値をハードコードしない
作成後、このスキルの使い方（呼び出し方）を教えてください。
```

**狙い**：試行錯誤の成果を**再利用可能な資産**に変える。内製化・横展開の物語の核。SKILL.mdの型を体験する。

**想定つまずき・助け舟**
- 会社固有の値が残る → 「5857 など特定企業に依存した記述を引数化して」。
- 手順が抽象的すぎる／具体的すぎる → 「別の人が読んで再現できる粒度に」と調整。

## 課題4：別企業の有報XBRLにスキルを適用（横展開・時間計測）

**プロンプト（コピペ）**
```
先ほど作った edinet-dashboard スキルを使って、./data/edinet/<別の会社コード>/ のXBRLから
同じ財務ダッシュボードを生成してください。1社目との違い（勘定科目やタグの差異）があれば、
スキル側を最小限だけ直して対応してください。
かかった時間の体感も教えてください（1社目より速くなっているはず）。
```

**狙い**：「1社目は試行錯誤、2社目は数分」を体感し、**工数削減率＋再利用の効き目**を実感（＝効果測定データにも直結、競合調査自動化の訴求にも接続）。

**想定つまずき・助け舟**
- 2社目でタグが合わない → 「差分だけスキルに追記して、汎用化して」。エラーはそのまま貼って直してもらう。
- ここで「スキルが育つ」感覚を言語化してもらうと定着に効く。

## 補足A：CLAUDE.md でコンテキストを渡す（精度アップの実演）

作業フォルダに `CLAUDE.md` を置くと、毎回の指示なしに前提を共有できます。第2回では「置く前／置いた後」で出力の質を比較すると効果が伝わります。

```
# このプロジェクトについて
- 対象データ: EDINET の有価証券報告書 XBRL（./data/edinet/<会社コード>/）
- 採用方針: 連結・通期の値を優先。単位は円、表示は億円に換算。
- 出力: ./output/ に financials.json と dashboard.html（外部ライブラリ不可・単一HTML）
- コーディング規約: 例外時は理由をログ出力。マジックナンバーは定数化。
```

## 補足B：うまくいくプロンプトのコツ（当日ひと言で）

- **ゴールと制約を先に**（「単一HTML・外部ライブラリなし・localhostで確認」）。
- **生の巨大データは貼らせない**（「本文は貼らず、対象タグと要約だけ」）＝コスト節約。
- **段階的に**（抽出 → 可視化 → 整形を分けて指示）。
- **エラーはそのまま渡す**（貼れば直してくれる）。
- **確認を挟む**（「開いて一緒に確認しよう」）。
