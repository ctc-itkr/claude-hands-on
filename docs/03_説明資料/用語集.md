# Claude Code ハンズオン 用語集

Claude Code特有・この案件特有の用語をまとめたもの。

## Claude Code特有の用語

### 1. エージェント（自律型AI）とは
- **定義**：指示に答えるだけの"チャット"と違い、**ファイルを読む/書く・コマンドを実行する・結果を見て自分で直す**を繰り返して、タスクを最後までやり切るAI。
- **ポイント**：人に例えると「調べて、手を動かして、動作確認して、直す」まで自分で回す新人。あなた（利用者）は方針とゴールを与え、要所で確認するだけでよい。
- **使いどころ**：XBRLの解析→ダッシュボード生成→修正、という一連をエージェントが自走する。これがClaude Codeの価値の中心。
- **間違えやすい点**：文章を返すだけの生成AIではない。"実行して直す"ループがある点が本質。

### 2. スキル（SKILL.md）とは
- **定義**：作業の「やり方」をファイル（`SKILL.md`）にまとめた**再利用パーツ**。毎回説明しなくてよくなる。
- **ポイント**：人でいう「手順書＋道具箱」。必要なときClaudeが自動で読み込み、その手順どおり動く。一度作れば**誰でも同じ品質で再現・横展開**できる。
- **使いどころ**：XBRL→ダッシュボードの手順をスキル化すれば、別企業でも一発。属人化を防ぐ"内製の資産"になる（このあとのスキル化の演習で体験する）。
- **間違えやすい点**：単発プロンプト＝その場限り／スキル＝再利用資産。MCP（外部ツール接続）とは別物。

### 3. CLAUDE.md とは
- **定義**：作業フォルダに置く「このプロジェクトの前提メモ」。Claudeが毎回自動で参照する。
- **ポイント**：データの場所・採用ルール（連結/通期、単位）・コーディング規約などを書いておくと、毎回指示しなくても品質が安定する。
- **使いどころ**：CLAUDE.mdを「置く前／置いた後」で、出力の質が変わるのを体験できる。
- **間違えやすい点**：スキルが"手順"なのに対し、CLAUDE.mdは"前提・文脈"。役割が違う。

### 4. メモリ機能（Auto Memory）とは
- **定義**：Claudeが対話から**自動で覚える学習ノート**。CLAUDE.mdが"人が書く前提"なのに対し、こちらは"Claudeが勝手に貯める経験"。
- **ポイント**：あなたのロール・与えた修正・進行中の判断・参照先などを、Claudeが必要と判断した分だけ記録（`~/.claude/projects/<repo>/memory/` に `MEMORY.md`＋トピック別ファイル）。`/memory` で確認・編集でき、既定でON。**マシンローカル＆リポジトリ単位**で、複数マシン間では共有されない。
- **使いどころ**：2社目・3社目と進めるうちに、一度直した好み（例：金額は億円、銀行は営業CFを強調しない）が次から反映される。`/memory` で中身を確認できる。
- **間違えやすい点**：①CLAUDE.md（gitに乗る＝共有・再現できる"憲法"）とは別物で、メモリは個人・自動の層。**再現性はCLAUDE.md＋スキル、快適さはメモリ**。②APIの"Memory Tool"とも別物。③Bedrockでも挙動は同じ。

### 5. Bedrockバックエンドとは

![環境図（Bedrock＝頭脳／手元PC＝手）](環境図.svg)

- **定義**：**モデル（頭脳）はAWS Bedrock、実際の作業（ファイル操作・コマンド）は手元のPC**、という構成。
- **ポイント**：Claudeへの「考えて」はクラウド（Bedrock）に、「やって」は手元で実行される。認証はEntra ID連携のAPIキー。
- **使いどころ（通信の切り分け）**：明示的に不可なのは**MCP外部連携**。
- **間違えやすい点**：「Bedrockが外部通信できない＝pipやデータ取得も不可」ではない。層が違う。

### 6. トークン／コンテキストとは
- **定義**：Claudeが1回に読む/書く情報の量。**これがそのままコスト**（Bedrock課金、HyperBillingで可視化）。
- **ポイント**：会話に載せた文章・ファイルの中身すべてがトークンとして課金される。巨大データを丸ごと載せると急に増える。
- **使いどころ**：XBRLは巨大なので、**本文を貼らずスクリプトで処理し、結果だけ確認する**のがコスト最適。この作法が日々の費用対効果に直接つながる。
- **間違えやすい点**：「とりあえず全部貼れば正確」ではない。載せる情報を絞る方が速く・安く・正確なことが多い。

## 参考情報

### 7. Copilot との住み分け
- **定義**：Copilot＝市民開発・SaaS壁打ち・Office連携向け／Claude Code＝自律型エージェント・複雑データ処理・コード生成/大規模開発向け。
- **使いどころ**：「置き換え」ではなく用途の棲み分け。複雑なデータ処理・コード生成・内製化はClaude Codeの領域。

### 8. 権限確認・安全性
- **定義**：エージェントがコマンド実行やファイル変更をする前に**確認を挟める**。何をしようとしているか読んでから許可する。
- **使いどころ**：権限確認ダイアログは「エージェントが何をしようとしているか」を読むチャンス。内容を確認してから許可すればよい。

### 9. EDINET とは
- **定義**：金融庁が運営する**電子開示システム**。上場企業などの有価証券報告書・四半期報告書・大量保有価証券報告書告書などが**誰でも無料で閲覧・ダウンロード**できる。
- **ポイント**：「Electronic Disclosure for Investors' NETwork」の略。Web画面での手動ダウンロードのほか、**API（v2、要APIキー）**でプログラムから取得もできる。原則、直近5年程度の書類を保持。
- **使いどころ**：題材データの出どころ。AREホールディングス（5857）を含む各社の有価証券報告書XBRLがここで公開されている。今回は配布済みのデータを使う。
- **間違えやすい点**：EDINET＝データの提供元。XBRL＝そこで配られるデータの形式。

### 10. XBRL とは
- **定義**：有価証券報告書などを**機械可読にした構造化データ形式**（タグ付きの財務データ）。
- **ポイント**：タクソノミ（定義体系）・コンテキスト（期間・連結/単体）・ディメンションがあり、人が直接読むのは辛い＝だからAIを使う。
- **使いどころ**：人手では辛いこの構造を、Claude Codeに解かせてまとめて可視化するのが今回のテーマ。
