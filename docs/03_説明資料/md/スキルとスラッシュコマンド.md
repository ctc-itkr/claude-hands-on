# スキル と カスタムスラッシュコマンド（説明資料）

Claude Code を使ううえで混同しやすい2つ、**スキル**と**カスタムスラッシュコマンド**の違いと使い方をまとめる。

---

## 1. スキルとは

- **定義**：作業の「やり方（手順書）」と「道具（スクリプト等）」を**パッケージ化した再利用パーツ**。
- **正体**：`SKILL.md`（Claude向けの手順書）を中心にしたフォルダ一式。**スキル＝Pythonスクリプトそのものではない**。スクリプトは手順が呼ぶ"道具"として同梱されているだけ。
- **呼び出し**：**自動**が基本。Claudeが状況と`SKILL.md`の説明（description）を見て「これ使えそう」と判断し、自分で読み込んで実行する。
- **中身は厚い**：手順・補助ファイル・判断のコツ・トラブルシュートまで持てる。道具はPythonでもシェルでもNode.jsでも、あるいは道具なしの手順だけでもよい。

### 例：本プロジェクトの `edinet-xbrl-dashboard`
```
skills/edinet-xbrl-dashboard/
├─ SKILL.md          ← スキルの本体（いつ・どう使うかの説明書）
├─ scripts/          ← 道具（Python）
│   ├─ extract_financials.py
│   └─ build_dashboard.py
└─ assets/
    └─ dashboard_template.html   ← ひな形
```
`SKILL.md` に「有価証券報告書XBRLを渡されたら、この2つのPythonを順に実行してダッシュボードを作る」と書いてある。発動すると **Claude（エージェント）が自分のシェルでそのPythonを実行**する。

---

## 2. カスタムスラッシュコマンドとは

- **定義**：`.claude/commands/<名前>.md` に置く、**定型プロンプトのショートカット**。
- **呼び出し**：**手動**。`/名前 引数` と明示的に打って起動する。
- **中身は薄い**：基本は「Claudeへの指示文」1枚。`$ARGUMENTS` で引数を受け取れる。

### 例：`/edinet-dashboard`
```
.claude/commands/edinet-dashboard.md
```
```markdown
有価証券報告書XBRL（$ARGUMENTS）から財務ダッシュボードを作成して。
skills/edinet-xbrl-dashboard の手順に従い、
extract_financials.py → build_dashboard.py を実行し、dashboard.html を開いて確認する。
```
→ `/edinet-dashboard data/AREホールディングス_E21187` のように起動できる。

---

## 3. 違いの早わかり

![スキルとスラッシュの違い](../スキル_スラッシュ比較.svg)

|          | スキル                               | カスタムスラッシュコマンド   |
|----------|--------------------------------------|------------------------------|
| 何か     | 手順書＋道具のパッケージ             | 定型プロンプト1枚            |
| 置き場所 | `skills/<名前>/SKILL.md`             | `.claude/commands/<名前>.md` |
| 呼び出し | **自動**（Claudeが判断）             | **手動**（`/名前`と打つ）    |
| 中身     | 手順・スクリプト・コツまで厚く持てる | Claudeへの指示文が中心       |
| 向くこと | 複雑な処理の再利用・横展開           | 決まった入口を1つ用意する    |

**一言でいうと**：スキル＝**Claudeが必要なときに自分で取り出す能力**／スラッシュコマンド＝**人が明示的に打つ定型指示**。

---

## 4. 組み合わせられる

両者は排他ではない。スラッシュコマンドの中身を「◯◯スキルの手順で実行して」とすれば、**人が`/`で起動 → 中でスキルが動く**という橋渡しになる。入口が1つに決まるので、迷わず起動できる。

---

## 5. ユーザー視点での使い方（いちばん大事）

普段は**難しく考えず、日本語で頼むだけ**でよい。

```
この有価証券報告書XBRLを財務ダッシュボードにして
→ data/AREホールディングス_E21187 のXBRL
```

これだけで、Claudeが裏で `edinet-xbrl-dashboard` スキルを選び、Pythonの実行まで全部やって `dashboard.html` を返す。**コマンドを覚える必要も、Pythonを自分で打つ必要もない。**

- **明示的に呼ばなくていい**：「有価証券報告書」「XBRL」「財務を可視化して」等でClaudeが自動で気づく。
- **入力を渡すだけ**：XBRLのZIP／解凍フォルダ／`.xbrl`ファイルのパスを伝える。
- **横展開も同じ**：「次はこの会社のXBRLで同じものを」でそのまま再適用。
- **確実に同じ入口で起動したい人向け**にだけ、`/edinet-dashboard <パス>` のスラッシュを用意しておくとよい。

> 基本は **「まず日本語で頼む」**。確実に同じ入口で起動したいときだけスラッシュを使う、の二本立てでよい。
