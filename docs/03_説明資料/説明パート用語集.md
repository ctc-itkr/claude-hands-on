# Claude Code ハンズオン 説明パート（用語集・第1回の下敷き）

第1回で使う概念説明の台本。**エンジニア対象なので既知のこと（git・ローカルサーバ・Python等）は説明せず、「エージェントという新概念」と「この案件特有の環境」に集中**。各項目は「一言 → 補足 → 今回の文脈 → よくある誤解」。目安：**必須5項目で合計15分前後**、あると良い項目は必要に応じて。座学で固めすぎず「説明1分→即デモ」で回収するのがコツ。

## いちばん大事なマインドセット：まず Claude に聞く

- **困ったら、調べる前にまず Claude に聞く。** 使い方・エラー・「これできる？」の大半は、その場の対話で解決します。
- **具体的には**：エラーメッセージはそのまま貼る／「〜をやりたい、どうすれば？」と素直に聞く／知らない用語は「〜って何？」で聞く／進め方に迷ったら相談する。
- **完璧なプロンプトを目指さなくていい**。対話しながら精度を上げる（＝プロンプトを"育てる"）のが前提。
- 「分からない」は詰まる理由になりません。**まず聞く方が結果的に速い**——これが定着の一番のコツ。当日も「まず聞いてみましょう」を合言葉に。

## 必須（Claude Code特有・今回の肝）

### 1. エージェント（自律型AI）とは
- **一言**：指示に答えるだけの"チャット"と違い、**ファイルを読む/書く・コマンドを実行する・結果を見て自分で直す**を繰り返して、タスクを最後までやり切るAI。
- **補足**：人に例えると「調べて、手を動かして、動作確認して、直す」まで自分で回す新人。こちらは方針とゴールを与え、要所で確認する。
- **今回の文脈**：XBRLの解析→ダッシュボード生成→修正、という一連をエージェントが自走する。これがClaude Codeの価値の中心。
- **よくある誤解**：文章を返すだけの生成AIではない。"実行して直す"ループがある点が本質。

### 2. スキル（SKILL.md）とは
- **一言**：作業の「やり方」をファイル（`SKILL.md`）にまとめた**再利用パーツ**。毎回説明しなくてよくなる。
- **補足**：人でいう「手順書＋道具箱」。必要なときClaudeが自動で読み込み、その手順どおり動く。一度作れば**誰でも同じ品質で再現・横展開**できる。
- **今回の文脈**：XBRL→ダッシュボードの手順をスキル化すれば、別企業でも一発。属人化を防ぐ"内製の資産"になる（第2回の課題3・4）。
- **よくある誤解**：単発プロンプト＝その場限り／スキル＝再利用資産。MCP（外部ツール接続）とは別物。

### 3. CLAUDE.md とは
- **一言**：作業フォルダに置く「このプロジェクトの前提メモ」。Claudeが毎回自動で参照する。
- **補足**：データの場所・採用ルール（連結/通期、単位）・コーディング規約などを書いておくと、毎回指示しなくても品質が安定する。
- **今回の文脈**：「置く前／置いた後」で出力の質を比較すると効果が伝わる（第2回・補足A）。
- **よくある誤解**：スキルが"手順"なのに対し、CLAUDE.mdは"前提・文脈"。役割が違う。

### 4. Bedrockバックエンドとは
- **一言**：**モデル（頭脳）はAWS Bedrock、実際の作業（ファイル操作・コマンド）は手元のPC**、という構成。
- **補足**：Claudeへの「考えて」はクラウド（Bedrock）に、「やって」は手元で実行される。認証はEntra ID連携のAPIキー、リージョンは東京。
- **今回の文脈（通信の切り分け）**：明示的に不可なのは**MCP外部連携だけ**。`pip`やEDINET取得は「手元PCがその先に出られるか」次第で、Bedrockの通信可否とは無関係。
- **よくある誤解**：「Bedrockが外部通信できない＝pipやデータ取得も不可」ではない。層が違う。

### 5. トークン／コンテキストとは
- **一言**：Claudeが1回に読む/書く情報の量。**これがそのままコスト**（Bedrock課金、HyperBillingで可視化）。
- **補足**：会話に載せた文章・ファイルの中身すべてがトークンとして課金される。巨大データを丸ごと載せると一気に増える。
- **今回の文脈**：XBRLは巨大なので**本文を貼らせず、スクリプトで処理して結果だけ確認**するのがコスト最適。この作法自体が定着後の費用対効果に直結。
- **よくある誤解**：「とりあえず全部貼れば正確」ではない。載せる情報を絞る方が速く・安く・正確なことが多い。

## あると良い

### 6. Copilot との住み分け
- **一言**：Copilot＝市民開発・SaaS壁打ち・Office連携向け／Claude Code＝自律型エージェント・複雑データ処理・コード生成/大規模開発向け。
- **今回の文脈**：「置き換え」ではなく用途の棲み分け。今回の高度利用枠（内製化）はClaude Codeの領域。

### 7. 権限確認・安全性
- **一言**：エージェントがコマンド実行やファイル変更をする前に**確認を挟める**。何をしようとしているか読んでから許可する。
- **今回の文脈**：当日「権限確認ダイアログ＝エージェントの動きを読む練習」として扱うと不安が減る。

### 8. EDINET とは
- **一言**：金融庁が運営する**電子開示システム**。上場企業などの有価証券報告書・四半期報告書・大量保有報告書などが**誰でも無料で閲覧・ダウンロード**できる。
- **補足**：「Electronic Disclosure for Investors' NETwork」の略。Web画面での手動ダウンロードのほか、**API（v2、要APIキー）**でプログラムから取得もできる。原則、直近5年程度の書類を保持。
- **今回の文脈**：題材データの出どころ。AREホールディングス（5857）を含む各社の有報XBRLをここから入手する。取得は事前にファシリテーターが行い、当日はローカル配布が基本（安全網）。
- **よくある誤解**：EDINET＝データの提供元。XBRL＝そこで配られるデータの形式。別物。

### 9. XBRL とは
- **一言**：有価証券報告書などを**機械可読にした構造化データ形式**（タグ付きの財務データ）。
- **補足**：タクソノミ（定義体系）・コンテキスト（期間・連結/単体）・ディメンションがあり、人が直接読むのは辛い＝だからAIが効く。
- **今回の文脈**：この"辛さ"を見せてからClaude Codeに解かせると、価値が一番伝わる。

## 付録：有価証券報告書の手動ダウンロード手順（EDINET）

事前準備でファシリテーターが配布データを用意する手順。第1回では「手作業だとこう→自動化するとこう楽になる」の対比としても使える。egressが閉じている環境の"取得"代替にもなる。

1. **EDINETにアクセス**：ブラウザで `https://disclosure2.edinet-fsa.go.jp/` を開き、「書類検索」へ。
2. **企業を検索**：「書類簡易検索」で提出者/発行者名（例：ＡＲＥホールディングス）や証券コード（例：5857）を入力。**書類種別で「有価証券報告書」**に絞り、必要に応じて提出期間を指定して検索。（キーワードで探すなら「全文検索」タブ）
3. **対象書類を選ぶ**：検索結果一覧から、提出日・提出者を確認して目的の有価証券報告書を開く。
4. **形式を選んでダウンロード**：書類表示画面のダウンロード操作から形式を選択。
   - **XBRL**（ZIP）… 今回の題材はこれ。財務データ本体。
   - **PDF** … 閲覧用。
   - **CSV** … 主要数値の表形式（提供がある場合）。
5. **保存・展開**：ZIPを保存し解凍。中身はXBRLインスタンス（`.xbrl` / `.htm`）＋タクソノミ＋添付。これを配布フォルダ（例：`./data/edinet/5857/`）に配置する。
6. **複数期分**：直近5期分が必要なら、各年度の有価証券報告書を同じ手順で個別に取得する。

> 注意：EDINETは原則直近5年程度の保持。それ以前が必要な場合は取得可否を別途確認。配布・出典表記のルールも事前にチェック（用語集8参照）。
