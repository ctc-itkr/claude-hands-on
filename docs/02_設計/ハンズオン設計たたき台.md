# Claude Code ハンズオン設計（たたき台）

**目玉題材：EDINETのXBRL → localhostダッシュボード → スキル化 → 他社横展開**

> 大野さんへの共有用たたき台。第1回＝訴求＋デモ、第2回＝実機ハンズオン。所要は各回おおむね3時間想定（当日0.5人日×2回）。

## 0. 前提（確定条件）

- **対象**：Claude Codeを使うエンジニアのみ（Coworkは今回対象外）。スキルレベルは幅あり。参加者PCはWindowsの可能性あり（OS種類は要事前確認）。
- **実行環境**：**Claudeデスクトップアプリ＋バックエンドBedrock**を有力案とし、**1構成に統一・事前プロビジョニング**。CLIより敷居が低く、スキル幅の広い参加者・Win/Mac混在を吸収しやすく、環境構築の負担を下げられる。認証はEntra ID連携のAPIキー（3時間ローテーション）／東京リージョン想定。
- **制約（固定）**：**外部サービスへのMCP連携は案件制約で不可**。Web検索（WebSearchツール）も不可。
- **通信の切り分け（重要）**：同じPCから出る通信でも性質が違い、**明示的に不可なのはMCPだけ**。残りは「PCのegress＋許可ポリシー次第」で、Bedrockの通信可否とは無関係。
  - モデル呼び出し：PC→Bedrock（動作している以上、到達済み）
  - パッケージ取得（`pip`等）：PC→PyPI／社内ミラー（PCのegress次第）
  - データ取得（EDINET等）：PC→外部APIのスクリプトHTTP（PCのegress＋許可次第。MCPでもWebSearchでもない別物）
- **目的**：Claude Codeの内製化支援と、将来の開発案件拡大への布石。「導入したが使われない」を防ぐ＝定着。

## 1. 目玉シナリオ（3幕）と選定理由

### なぜこの題材か
- **XBRLは複雑で人手では辛い** → Claude Codeの得意領域「複雑データ解析」を最も分かりやすく見せられる。
- **対象顧客AREホールディングスは上場企業（東証プライム・5857・非鉄金属）** → 自社の有価証券報告書がEDINETにあり、参加者にとって「身近なデータ」。
- **スキル化で横展開できる** → 別企業の有報に一発適用でき、内製化・再利用資産化の物語に直結。
- **ダッシュボードで「簡単」「すごい」を演出** → 複雑データが一気に可視化される達成感で定着を後押し。

### 3幕
1. **取得と複雑さの体感**：有報XBRL（タクソノミ／コンテキスト／ディメンション）の辛さを見せ、Claude Codeに解析させる。
2. **試行錯誤でlocalhostダッシュボード**：主要財務数値を抽出し、ローカルで動くダッシュボードに。エージェントが自分で直しながら完成へ。
3. **スキル化 → 他社横展開**：手順を `SKILL.md` に固め、別企業の有報XBRLへ一発適用。「1社目は試行錯誤、2社目は数分」で工数削減と再利用資産化を同時に見せる（＝競合調査レポート自動化の訴求にも直結）。

### 取得（EDINET）の扱い
- EDINET取得も**PC上のスクリプトによる外部HTTP**なので、PCがEDINETエンドポイントに出られれば**ライブ取得も可能**（許可ポリシー次第、要確認）。
- ただしライブ外部取得は当日の事故要因（レート制限・多人数同時・キー切れ・一時不調）。→ **「ライブ取得＝ハッピーパス／事前DL配布＝安全網」の二段構え**にする。取得デモは代表者が1回見せ、各自課題は配布済みデータで確実に回す。
- egressが閉じている場合は、事前DL配布のみで完結させる。

## 5. 事前準備リスト（ファシリテーター）

**データ**
- EDINETから対象数社（本命＝AREホールディングス＋横展開用の同業他社1〜2社）の有報XBRL/ZIPを取得し、配布パッケージ化（＝当日の安全網）。
- **EDINET APIキー（Subscription-Key）**を事前取得（v2は登録制・無料）。ライブ取得デモをやる場合に使用。
- 各社データの**配布可否・出典表記**を確認。
- ダッシュボードの「期待する完成像」サンプルを用意（ゴールの共有用）。

**環境**
- デスクトップアプリ＋Bedrock：モデルID pin留め・東京/クロスリージョン推論プロファイル・APIキー配布の段取り。
- **パッケージ取得方針の確定**：PCがPyPI/社内ミラーに到達できるなら当日 `pip install` 可。到達不可なら解析ライブラリ（arelle 等）を環境同梱、または標準ライブラリ（ElementTree/lxml）＋単一HTML＋インラインJSで完結する構成に固定。
- 参加者PCのOS種類を事前確認し、導入手順をOS別に用意。
- オンサイト/リモート両対応（画面共有・投影確認）。

**教材**
- 課題0〜4のワークシート、期待アウトプット、詰まった時の“助け舟”スニペット。
- `SKILL.md` の型（スキル化のテンプレート）。
- 工数記録シート（課題ごとの所要時間、1社目 vs 2社目）。

## 7. リスク・ハマりどころと対策

| リスク | 対策 |
|--------|------|
| 外部通信不可で取得・パッケージ導入が失敗 | 取得は事前DL配布を安全網に、ライブは代表者のみ／ライブラリは環境同梱 or 標準ライブラリ構成 |
| XBRLがゼロからだと重い | 出発点（サンプル・雛形・段階化）を用意 |
| APIキーの3時間ローテで途中切れ | 開始直前に発行、再取得手順を事前共有 |
| OS/導入方法のばらつき | 1構成に統一、事前プロビジョニング |
| Skills Marketplaceが使えない | 自作スキルで完結（Marketplaceは使わない） |
| スキルレベル差で脱落 | 課題0で全員成功体験、助け舟スニペット、ペア/伴走 |
