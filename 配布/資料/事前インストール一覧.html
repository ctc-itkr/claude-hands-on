ハンズオン セットアップ手順（Windows）

Claude Cowork ＋ Code 同日ハンズオン セットアップ手順

同じ日に行う「Claude Cowork」と「Claude Code」の両方のハンズオンで使う、Windows PC のセットアップ手順をまとめています。各 PC でインストールと設定を行う担当者の方に向けた資料です。上から順に進めていただくと、両方のハンズオンが動く状態になります。

前提：インフラ準備（AWS）→ STEP 1：インストール→ STEP 2：Claude Desktop 設定→ STEP 3：MCP 設定→ STEP 4：動作確認
本書は各 PC のセットアップを対象としています。各ステップには、Cowork と Code のどちらで必要かを示すラベルを付けています。接続に使う値（APIキー・リージョン・モデルID）や、演習で使うデータ・教材は、別途配布・案内いたします。
※ 各設定画面の操作イメージについては、本手順の元にした AWS Japan の記事（zenn.dev：aws-bedrock-claude-cowork-setup）を併せてご参照ください。本書では画面キャプチャは転載していません。

凡例

共通 Cowork と Code の両方で必要です Cowork Cowork で必要です Code Code で必要です インフラ AWS 管理者が行う前提作業です 任意 行わなくても進められます

前提インフラ準備（AWS）担当：AWS 管理者

本手順を始める前に、AWS 側で Bedrock の準備が完了している必要があります。ここは AWS 管理者が行う前提作業です。この作業が終わると、各 PC のセットアップに使う接続情報（APIキー・リージョン・モデルID）が配布されます。

AWS 管理者が行うことの概要です。
  1. Bedrock の Quota を確認します。値が 0 や極端に低い場合は、営業または AWS Support に問い合わせます。
  2. Bedrock の Playground で対象モデル（例：Opus・Sonnet・Haiku）を選び、Use case を入力して利用を有効化します。
  3. IAM で、Bearer Token 用のアクション（bedrock:CallWithBearerToken・bedrock:InvokeModel など）と Marketplace のサブスクリプション権限を持つポリシーを作成し、IAM ユーザーにアタッチします。
  4. そのユーザーの Security credentials で、Service を Amazon Bedrock として APIキーを発行します。表示は一度きりなので控えておきます。
  5. 発行した APIキー・リージョン・モデルID を、各 PC のセットアップ担当へ共有します。
※ IAM ポリシーの具体的な内容や各画面の操作については、zenn 記事の該当章（AWS／Bedrock の準備）をご参照ください。

STEP 1各 PC にインストール担当：セットアップ者

まずは必要なソフトを入れていきます。VM 機能の有効化や Git・Node.js のインストールには管理者権限が必要です（GPO／Intune での一括展開も可能です）。下の表が全体像で、続けて各手順を説明します。

インストールするものCoworkCode区分
1. Claude デスクトップアプリ✓✓共通
2. Git for Windows（Git Bash）✓✓共通
3. Node.js✓—Cowork
4. uv✓—Cowork

1

Claude デスクトップアプリ（Windows 版）

共通

研修の本体です。Cowork と Code のどちらも、このアプリから操作します。公式サイト claude.com/download から Windows 版をダウンロードして、インストールしてください。

2

Git for Windows（Git Bash）

共通

Claude が Python やコマンドを実行する際のシェル（bash）として使います。Windows には bash が標準で入っていないため、Git に付属する Git Bash を利用します。git-scm.com/download/win から、既定の設定のままインストールしてください。

インストールした bash を Claude に使わせる設定は、このあとの STEP 2（2-3）で行います。

3

Node.js

Cowork

Cowork では、MCP サーバーを npx で起動するために Node.js を使います。nodejs.org の LTS 版インストーラを、既定の設定でインストールしてください。

4

uv

Cowork

Cowork の一部の MCP サーバーの起動に使います。PowerShell で、次のコマンドを実行してインストールしてください（公式インストーラです）。

powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
5

Google Chrome

共通

Cowork では、Chrome DevTools の MCP で Chrome を使います。google.com/chrome からインストールしてください。

Code だけを行う場合は、作成した dashboard.html の表示や EDINET の閲覧に使うだけなので、既定のブラウザでも代用できます。そのため Code のみであれば Chrome のインストールは任意です。

6

仮想マシンプラットフォーム（Windows の機能）

Cowork

Cowork は内部で小さな Linux 仮想マシンを動かすため、この Windows 機能を有効化します。「Windows の機能の有効化または無効化」から有効にするか、管理者の PowerShell で次のコマンドを実行してください。

Enable-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform

有効化したら PC を再起動してください。Cowork の readiness check を使うと、PC がスペック要件を満たしているかを確認できます。

7

Python 3.x

Code

Code の研修では「Claude がその場でプログラムを書いて実行する」体験を行い、その実行に Python を使います。Windows には標準で搭載されていないため、インストールが必要です。次のいずれかの方法で入れてください。

  1. python.org のインストーラを使う場合は、最初の画面で「Add python.exe to PATH」にチェックを入れてください。
  2. Microsoft Store 版を使う場合は、管理者権限なしで導入でき、python3 コマンドも使えます。

サポートが継続している Python 3 系であれば、入手方法は問いません。インストールが終わったら、PowerShell で python --version（Microsoft Store 版の場合は python3 --version）を実行し、バージョンが表示されれば完了です。

STEP 2Claude Desktop の設定担当：セットアップ者

アプリに、Bedrock への接続とシェルを設定します。入力する接続値（APIキー・リージョン・モデルID）は、前提（インフラ）で配布されたものを使います。

各設定画面の操作イメージは、zenn 記事の該当章（Claude Desktop の設定）をご参照ください。

2-1

開発者モードを有効にする

共通

アプリの「ヘルプ」から「トラブルシューティング」を開き、開発者モードを有効にします。このあとの接続設定や MCP 設定で必要になります。

2-2

Bedrock に接続する（サードパーティ推論）

共通

サードパーティ推論の設定画面で、次のように設定してください。

  1. 認証情報の種類を「静的APIキー」にします。
  2. 配布されたリージョンと APIキー（トークン）を入力し、接続テストを行います。
  3. モデル検出を OFF にします。
  4. モデルID を登録します（例：global.anthropic.claude-sonnet-4-6 など。実際の値は配布されたものを使ってください）。
2-3

Git Bash をシェルとして設定する

共通

STEP 1 の手順 2（Git for Windows）でインストールした Git Bash を、Claude が使うシェルとして指定します。次の2つを設定してください。

  1. 環境変数 CLAUDE_CODE_GIT_BASH_PATH に、Git Bash（bash.exe）のパスを設定します。たとえば C:\Program Files\Git\bin\bash.exe のようになります。
  2. %USERPROFILE%\.claude\settings.json の SHELL に、bash.exe を指定します。

STEP 3MCP を設定する担当：セットアップ者

MCP（Model Context Protocol）は、Claude に外部ツールを連携させる仕組みです。Cowork では次の2つを設定します。これらを動かす実体は、先にインストールした Node.js と Chrome です。

各 MCP の設定画面の操作イメージは、zenn 記事の該当章（MCP の設定）をご参照ください。

3-1

Web 検索の MCP サーバー（brave-search）

CoworkMCP任意

Brave Search を MCP サーバーとして利用します。npx で起動するため、Node.js を使います。利用には Brave の APIキーが必要で、AWS Marketplace から取得して登録します。

brave-search は外部の Web 検索を行う MCP です。外部 MCP や Web 検索を使えるかどうかは案件の方針によって異なりますので、ご利用方針を確認したうえで設定してください。方針上使わない場合は、この項目は設定しなくても問題ありません。

3-2

ブラウザ操作の MCP サーバー（chrome-devtools）

CoworkMCP

Chrome の操作やデバッグを MCP から行います。ブラウザの実体は、先にインストールした Chrome です。Chrome で chrome://inspect/#remote-debugging を開き、リモートデバッグを ON にしてください。

設定を変更したら、Claude デスクトップアプリをタスクトレイから一度終了し、起動し直してください。これで設定が反映されます。

STEP 4動作を確認する担当：セットアップ者

最後に、それぞれが動くことを確認します。

Code の確認： アプリの「Code」タブを開き、Local から作業フォルダを選択します。そのうえで「Python で hello world を書いて実行して」と指示し、実行できれば準備完了です。
Cowork の確認： readiness check で要件を確認したうえで Cowork を起動し、指示が通れば準備完了です。

補足

  • 管理者権限について： 仮想マシンプラットフォームの有効化や、Git・Node.js のインストールには管理者権限が必要です。GPO／Intune での一括展開も可能です。
  • シェルについて： 本書では Git Bash に統一しています。Windows 標準の PowerShell をシェルにする環境変数方式もありますが、Cowork が Git Bash を使うため、こちらに揃えています。
  • 以前の設定が残っている場合： claude_desktop_config.json に古い mcpServers が残っているときは、それを削除してから、画面で設定し直してください。
