Claude Code と Cowork のしくみ

しくみの比較 · Code / Cowork / Bedrock

「考える」はいつもクラウド。
違いは「実処理」の場所。

「モデルが考える」（推論）は常にクラウド（Anthropic か、自社の Bedrock）で、そこは共通です。分かれるのは「実処理（手足）」をどこで・どう隔離して動かすか。ここに Claude Code・Cowork（2つの実行モード） の違いがあります。

Bedrock を加えると

Bedrock の使われ方は2通り

Bedrock は ①「素の API」で考える箱だけを使い自前でアプリを作る 使い方と、② Cowork / Claude Code の "推論バックエンド" にする（製品はそのまま、推論とデータだけ自社 AWS に向ける）使い方があります。下表の「Bedrock」列は①（素材として使う）を示しています。

共通

考えるのはクラウド

「次に何をするか」を決めるモデル推論は常にクラウド上（Anthropic、または自社の Bedrock）。モデル本体がローカルに落ちて動くわけではない。

Claude Code

手足はホスト直接

コード・コマンドを手元 PC のホスト OS 上で直接実行。実ファイル・git にそのまま触れ、低遅延で密結合できるのが武器（隔離なし）。

Cowork

手足は隔離環境（2モード）

実処理は、Anthropic クラウドの隔離サンドボックス（クラウド実行）か、手元 PC 上の隔離 VM（ローカル実行）で動く。Code と違いホストに直接は触れない。

Bedrock

考える箱を自社 AWS に

素の API なら「考える箱」だけの素材（手足・UX は自作）。または Cowork / Code の推論バックエンドにして、製品はそのまま推論とデータを自社 AWS 内に閉じる。

Cowork ならでは（クラウド実行モード）

手足をクラウドの隔離サンドボックスで動かす「クラウド実行モード」から派生する性質。ここが Claude Code との実用上の差になる（ローカル実行モードでは PC の稼働が前提になる点に注意）。

PC を閉じても継続長い処理を投げてノート PC を閉じても、クラウド側で走り続ける。
定期実行・予約（cron 的）「毎朝まとめて通知」「1時間後に確認」を自然言語の指示で。発火ごとに新セッションが立つ。
デバイス横断デスクトップで始めてスマホから続きを確認、といった横断ができる。
成果物の永続化・共有スライドやシート等が claude.ai 上に残り、後から開き直す・更新する・共有できる。

※ 「PC を閉じても継続／デバイス横断」はクラウド実行モードの性質。ローカル実行モード（デスクトップ VM）や Bedrock バックエンド構成では、実処理が手元で動くため PC の稼働が前提になる。正式提案では採用構成（クラウド／ローカル／Bedrock）ごとに挙動を要確認。
